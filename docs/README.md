# 项目文档索引

本项目在 Ascend 910B1 八卡服务器上，使用 vLLM-Ascend 部署本地模型，适配 Datacurve DeepSWE，逐步研究推理优化对任务成功率、性能和资源开销的影响。

文档用于记录研究过程，也用于学习回顾。建议从 00 号文档开始，按编号阅读。

## 文档记录规则

### 编号与文件名

- 使用 `NN-主题.md`，例如 `01-模型部署与首次推理.md`。编号至少两位，按实际研究顺序递增。
- 新增一篇文档时，同时更新本索引；未开始的工作不创建空白编号文档。
- 一篇文档围绕一个研究问题或一个完整阶段，既记录成功结果，也记录影响结论的失败尝试。
- 日期和时间统一使用 Asia/Shanghai（UTC+8）。

### 每篇研究记录应包含什么

| 内容 | 需要回答的问题 |
| --- | --- |
| 日期、阶段与状态 | 什么时候进行？已完成、部分完成，还是待验证？ |
| 问题与学习目标 | 这次要弄清什么？涉及哪些推理概念？ |
| 原理与预期 | 为什么采用这个方案？预期会发生什么？ |
| 环境与控制变量 | 模型、权重版本、代码提交、镜像、参数和任务集是什么？相较上一次改变了什么？ |
| 操作与复现 | 实际执行了哪些命令？脚本和配置在哪里？ |
| 结果与证据 | 观察到什么？日志、原始结果和指标在哪里？ |
| 失败与处理 | 出现了什么问题？如何定位？哪些方法没有解决问题？ |
| 结论与边界 | 证据支持什么结论？还有哪些不能确认？ |
| 后续工作 | 下一步要解决什么？以什么结果作为通过条件？ |

具体章节可按任务调整；简单记录可以精简，但实验环境、证据和结论边界不能省略。

### 如何维护历史

- 明确标注“实测事实”“外部资料”“推测”“计划”，避免把配置生成、镜像构建、参考解答通过和模型评测通过混为一谈。
- 原始日志和结构化结果保留在实验目录，文档链接到证据，不用手工改写的汇总替代原始数据。
- 旧结论发生变化时，保留原结论的上下文，并补充带日期的更正或后续文档链接。
- 00 号文档是项目起步时的基线快照；后续实验按新编号记录。重要选型变化在 00 号文档追加变更记录，避免读者把旧配置当作当前配置。
- 性能指标区分模型服务指标和 Agent 端到端指标；精度结论注明任务版本、Agent、采样配置、预算、样本范围和重复次数。
